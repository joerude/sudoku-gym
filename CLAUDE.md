## Wiki: Sudoku Gym

Знание о скоростном решении судоку и о прогрессе ученика (usdoku.com, medium и hardcore; цель — medium за 4 мин): конспекты источников, разборы партий из БД тренажёра, тренировочные эксперименты и решения. Код тренажёра живёт в корне проекта, вики — в `wiki/`.

Устроено по паттерну «LLM Wiki» (Karpathy): знание копится в постоянной вики, а не выводится заново из сырья при каждом вопросе. Параметры (`.claude/claude-setup.json`): корень `wiki/`, ссылки `md`, порядок `log.md` — `append`. Пути ниже — от корня вики.

### Слои

| Слой | Что | Кто пишет |
| --- | --- | --- |
| Сырьё | `input/` (зона сброса) → сырьевые пути из профиля | владелец приносит; после разбора неизменяемо |
| Вики | страницы из «Карта wiki» | агент ведёт; владелец читает и подтверждает |
| Схема | этот блок, `templates/` | меняется только по согласованию с владельцем |

Владелец курирует источники, задаёт вопросы, подтверждает. Агент ведёт «бухгалтерию»: разносит факты по страницам, держит перекрёстные ссылки, ловит противоречия, обновляет `index.md`, `log.md`, `BACKLOG.md`.

### Карта wiki

| Путь | Что | Правила |
| --- | --- | --- |
| `index.md` | каталог: ссылка + одна строка сути на каждую страницу | читать первым; обновлять при любом изменении состава или сути страниц |
| `log.md` | журнал операций | старое не правится; формат — «Формат log.md» |
| `BACKLOG.md` | открытые вопросы, UNKNOWN, CONFLICTING | у каждой строки «зачем»; закрытие — с датой и ссылкой на факт |
| `ideas-parking.md` | идеи одной строкой | статусы `parked` / `rejected` / `accepted` (→ решение) |
| `input/` | новые материалы | после разбора пуста |
| `sources/` | конспекты внешних источников | файл на источник по `templates/source.md` |
| `analysis/` | аналитика поверх фактов | только со ссылками на факты; ограничения фазы |
| `decisions/` | решения — принятые И отклонённые | `ГГГГ-ММ-ДД-slug.md` по `templates/decision.md` |
| `experiments/` | обратимые эксперименты | `ГГГГ-ММ-ДД-slug.md` по `templates/experiment.md` |
| `templates/` | шаблоны страниц | новый тип документа → сначала шаблон |

Доменные страницы и отличия от этой карты — в «Профиль домена» (он главнее). Директории создаются при первой странице; новые верхнеуровневые — только по согласованию.

Ссылки: `md` — `[текст](относительный/путь.md)` от текущей страницы; `wikilink` — `[[slug]]`, slug = имя файла без `.md`, уникален в вики. Указатель на источник факта `→ путь` пишется одинаково в обоих стилях.

### Уровни достоверности

Шкала, выше — сильнее; доменные уровни встают в неё по профилю:

| Уровень | Значение |
| --- | --- |
| MEASURED | измерено или проверено лично: инструмент, тест, запуск; обязательны дата и что именно |
| OWNER_VERIFIED | владелец подтвердил лично, без измерения |
| PRIMARY_SOURCE | первоисточник: официальный документ, договор, спецификация, паспорт изделия, официальная документация |
| SECONDARY_SOURCE | сайт, статья, обзор, форум, объявление |
| INFERRED | выведено из других фактов; указать исходники и логику; не сильнее слабейшего исходника |

Вне шкалы: **CONFLICTING** — источники противоречат без явного победителя: записать ВСЕ значения с источниками + строка в BACKLOG; **UNKNOWN** — честное «не знаем» + строка в BACKLOG; заполнять догадкой запрещено.

1. Факт без уровня и источника недействителен.
2. Повышение уровня — только с новым источником (ссылка обязательна); история изменений — git.
3. Конфликт разных уровней: побеждает старший, младшее значение остаётся в примечании.
4. Конфликт равных уровней: CONFLICTING + BACKLOG. Противоречия никогда не перезаписываются молча.
5. Субъективное (боли, привычки, предпочтения владельца) уровня не требует — владелец первоисточник; дата обязательна.
6. Факт большего масштаба не применяется к меньшему автоматически — только через проверку на целевом масштабе (масштабы — в профиле).
7. Не выдумывать, не округлять, не усреднять.

Формат факта: `значение [УРОВЕНЬ, ГГГГ-ММ-ДД, → путь/к/источнику]`; в таблицах — колонки «Значение | Уровень | Источник | Дата». Даты ISO. Насколько строго — «Строгость фактов» в профиле.

Противоречие на странице: `CONFLICTING` у факта со всеми значениями или блок `> ⚠ Противоречие: …` со ссылками на оба источника; в обоих случаях — строка в BACKLOG.

### Операции: Ingest · Query · Lint

Skills: `/claude-setup:wiki-ingest`, `/claude-setup:wiki-query`, `/claude-setup:wiki-lint`.

**Ingest — приём материалов.**
1. Материалы приходят в чат или в `input/`. Файл из чата агент сохранить не может: владелец кладёт его в `input/`; до тех пор он описывается с пометкой «файл не передан».
2. Сырьё — переименовать по конвенции профиля и перенести в сырьевой слой; существующее сырьё не редактировать и не удалять.
3. Извлечь факты (уровень + источник + дата) и наблюдения на страницы.
4. Распространить: один материал обычно затрагивает несколько страниц — обновить ВСЕ связанные; противоречия — по «Уровни достоверности».
5. Закрыть отвеченное в BACKLOG, обновить `index.md`, запись `ingest` в `log.md`, коммит на порцию.

**Query — ответ на вопрос.**
1. `index.md` → нужные страницы; к сырью — только если вики не хватает.
2. Ответ ссылается на страницы и факты с уровнями; UNKNOWN называется прямо, без догадок.
3. Ответ с долгосрочной ценностью (сравнение, расчёт, разбор) сохраняется страницей — `analysis/` или по профилю, с учётом фазы; затем `index.md` + `log.md`. Знание не должно жить только в чате.
4. Пробелы данных → BACKLOG.

**Lint — здоровье вики.** По запросу или примерно раз в 10 ingest. Проверяется: битые ссылки (`[..](..)`, `[[..]]`, `→ путь`); сироты и страницы вне `index.md`; перекрёстные ссылки из профиля; противоречия без пометки; устаревшее (UNKNOWN, на который есть ответ; открытые пункты BACKLOG, закрытые фактами); факты без уровня/источника/даты; формат `log.md`; нарушения профиля (имена сырья, единицы, ID). Механическое — сразу; требующее данных или решения владельца → BACKLOG. Итог — запись `lint`.

### Формат log.md

Порядок `append`: `append` — новые записи в конец; `prepend` — сверху, сразу под шапкой. Старые записи не правятся и не удаляются.

Запись по умолчанию: `## [ГГГГ-ММ-ДД] <операция> | <заголовок>` + 1–4 пункта: что изменилось, ключевые файлы/ID. Хеш коммита не пишется: запись входит в тот же коммит (`git log -- log.md`). Иной формат — только если он объявлен в шапке `log.md` и в профиле.

Операции: `init`, `ingest`, `query`, `lint`, `decision`, `experiment`, `schema` (CLAUDE.md, шаблоны, структура).

### Решения и эксперименты

- **Фаза** (профиль) задаёт, что агент делает по умолчанию. Вне фазы — только по явному запросу владельца; иначе идея одной строкой в `ideas-parking.md`: `- ГГГГ-ММ-ДД — идея — статус: parked | rejected (→ решение) | accepted (→ решение)`.
- **Решение** — принятое ИЛИ отклонённое → `decisions/` по `templates/decision.md`: контекст, решение, обоснование, отклонённые альтернативы, условия пересмотра. При REJECTED/CANCELLED обязательно «почему», чтобы идею не предлагали повторно. Отказы одного разбора можно собрать в один файл.
- **Эксперимент** → `experiments/` по `templates/experiment.md`: гипотеза, что меняем и что не трогаем, срок, метрики, критерии успеха/провала, откат. Статусы DESIGNED → RUNNING → EVALUATED; отмена до старта — CANCELLED с причиной. Итог — решение ACCEPTED / MODIFIED / REJECTED / TESTED_LONGER.
- Анализ и предложения — не факты и не решения: в факты попадают только через подтверждение.
- Пункты BACKLOG с пометкой «отложено владельцем» не напоминать и не выпячивать; менее затратную альтернативу предложить один раз.

### Конец сессии

BACKLOG актуален (отвеченное закрыто, новое — с «зачем») · `index.md` отражает состав вики · запись в `log.md` · git-коммит, если вики под git (не в `.gitignore`). В коммитах и файлах — никаких AI-трейлеров (`Co-Authored-By: Claude…`, `Generated with Claude Code`): требование владельца.

| Задача | Кому | Агент |

Задание делегату самодостаточно: цель, пути, критерий готовности, что не трогать (разговор он не видит). Результат проверяется выборочно по файлам, а не по пересказу. Делегаты не коммитят и не правят `index.md`/`log.md`. На Sonnet/Haiku делегирование не обязательно.

### Профиль домена

Заполняет `/claude-setup:setup`, правит владелец. «нет» — правило не действует; профиль главнее ядра там, где они расходятся.

- **Фаза**: ТРЕНИРОВКА — по умолчанию: разбор источников о скоростном решении, анализ партий и упражнений из `data/sudoku.db`, тренировочные эксперименты (что меняем в тренировке → метрики из БД). Новые фичи и правки кода тренажёра — только по явному запросу владельца; идеи → `ideas-parking.md`.
- **Сырьё** (пути и конвенция имён): `input/` → `raw/`, имена `ГГГГ-ММ-ДД__тип__что.ext` (тип: `article`, `video-notes`, `screenshot`, `export`…); статьи и скриншоты usdoku, заметки к видео. БД тренажёра `../data/sudoku.db` — источник MEASURED: читать только `mode=ro`, указатель `→ data/sudoku.db: <таблица или запрос>`; в `raw/` не копировать.
- **Карта: доменные страницы и отличия**: `topics/<slug>.md` — знания о скорости: старт на пустой сетке, сканирование, ввод, сравнения методов. Вне корня вики (ссылки `../…`, вики их не переписывает): `../theory/*.md` — теория, которую показывает тренажёр (продукт; правка — только по согласованию, затем пересборка образа); `../progress.md` — профиль и журнал сессий ученика, ведёт скилл `sudoku-speed-coach`; `../docs/superpowers/` — спеки и планы кода.
- **Формат страницы** (frontmatter и т. п.): нет (без frontmatter; frontmatter есть только у `../theory/*.md`, его формат задаёт тренажёр)
- **Строгость фактов**: `page` — `strict`: формат факта у каждого факта; `page`: источники и дата — во frontmatter страницы, уровень inline только у выведенных, спорных и неподтверждённых утверждений
- **Доменные уровни** (место в шкале): нет; уточнения шкалы: MEASURED — цифры из `data/sudoku.db` и партии в тренажёре (с id партии или запросом); время на usdoku со слов ученика — OWNER_VERIFIED; рекорды и статистика других игроков — SECONDARY_SOURCE, если нет официального рейтинга
- **Масштабы**: `УЧЕНИК` ≠ `ИГРОКИ ВООБЩЕ` (средние и рекорды других не применяются к ученику без замера); режимы `medium` ≠ `hardcore` и `тренажёр` ≠ `usdoku` — факт одного режима или площадки на другой не переносится автоматически
- **Идентификаторы** (ID не меняются и не переиспользуются): техники — slug как в тренажёре: `x_wing` в drills/БД, `x-wing` в `theory/`; партии и упражнения — id из БД
- **Единицы**: время `м:сс.с`, темп — с/ход, паузы — с; сложность — `tech_grade` 1–5; даты ISO
- **Формат записи log.md**: по умолчанию
- **Перекрёстные ссылки для Lint**: `topics/*` ↔ `../theory/<slug>.md` той же техники; `experiments/*` ↔ записи журнала в `../progress.md` за срок эксперимента
- **Доменные антиправила**: цифры прогресса — из БД, не по памяти ученика или чата; не выдумывать рекорды, нормативы и статистику игроков; в рамках ingest/query не править код, `../theory/` и `../progress.md` (только предложить); не выводить уровень ученика по одной партии
- **Дополнительные шаблоны**: нет
